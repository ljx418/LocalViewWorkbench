# S3 P3 产品集成架构裁决

负责人：root Codex。P2B闭环只接受真实跨OS的合成账本边界，不是产品Gate0。已批准的S2衔接继续有效，旧S2人签不再阻塞此衔接。

1. 保留原有生产owner和phase；新S3协调器负责封存、顺序、子授权、证据归集，不复制S2整套协调器。先将实际增量包接入原StageRuntimeFactory创建的同一个Comfy base-directory，消除另复制源码造成的包验收假绿。P3A详细合同见同目录p3-installed-runtime.contract.md。
2. 后续完整父批次分两个顺序子运行：A沿用原生生产矩阵，模型上限103；B承担独立10图6视频质量集（34动作）、冷启动图视频（至少5动作）及安装/回滚等补项。B最终上限由固定矩阵推导，尚未冻结，不猜测为64。两个子运行都按full=True计费，最多消耗两个有效完整槽位；不改变母授权128动作/child，不伪造full=False。父批次的候选、工具、模型、输入集合和环境必须同源；跨候选不拼接。
3. 质量驱动只接收asset-id/hash/media-reference与提示词身份；预标不进入模型输入。独立评分使用原始输出和冻结预标，10图至少8、6视频至少5可用、关键幻觉0。四帧不证明完整运动或物理运镜；未知不算已验证。
4. A06必须同时具备本轮临时非loopback阻断和受控外连尝试观察，现有no-cloud环境变量及已建立连接采样不充当替代。网络机制及权限能力尚未选定/验证；缺失时真实全批次仍不得启动。不得修改永久系统配置。原workflow须由实际注册节点和前后同源图绑定，不编造class_type。
5. P3A为离线生产接线实现，不启动任何原生服务，不作模型、GPU、媒体、网络、真实账本动作，不宣称完整S3启动参数/质量/回滚已验证。后续运行须先冻结完整产品Gate0和有限子授权。

剩余集成顺序：P3A安装产物接线 → 完整协调器/质量与A06细化 → 离线组合审查 → 产品Gate0 → 同源有限完整运行 → 独立验收 → 必要人工签署。内部接线不改变公共API、产品Schema、固定分母或历史门禁。
