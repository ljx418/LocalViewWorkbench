# LVW Agent Governance

版本：1.0.0（2026-10-27）

本目录把多项目、多 Agent 协作规则接入现有 MasterPack。它只管理“谁可以做什么、候选如何绑定、证据如何生成、Stage 如何裁决”，不复制或改写产品权威。

## 权威顺序

1. 用户当前明确授权。
2. `docs/00_POSITION_AND_ADR.md` 与批准的 ADR。
3. `contracts/`、`plans/requirements.json`、`plans/acceptance_cases.json`、`plans/release_gates.json`。
4. 当前冻结的 `.agent-governance/stages/<stage-id>/`。
5. 本目录的通用治理规则与模板。
6. `legacy/`，只读历史。

冲突不得静默覆盖。公共合同、固定分母、阈值或角色权限变化必须新建变更记录，由门禁负责人裁决并重新冻结 Stage Packet。

## 文件关系

- `roles.md`：角色、权限和四权分离。
- `routing-policy.md`：任务路由、预算和升级。
- `stage-gates.md`：Stage、Workpack、候选和门禁状态机。
- `parallel-execution.md`：跨项目队列、worktree 与资源隔离。
- `anti-false-green.md`：生产路径、证据和反假绿规则。
- `workflows/`：阶段生命周期的可测试工作流规范。
- `templates/`：可复用交接、收据、审查和裁决模板。
- `stages/V0-S0/`：首个真实 Stage Packet；当前只冻结流程，未执行目标机验收。
- `runtime/`：可变队列、收据和指标的接口说明；实际运行数据默认不提交源码仓库。
- `project-registry.json`：跨项目调度的项目入口；这里只登记LVW，不扫描或接管其他项目。
- `plans/execution-control.json`：唯一当前坐标。
- `tools/verify_governance.py`：确定性制度校验和反假绿负例自测。

## 固定状态边界

产品用例继续只使用 `NOT_RUN/PASS/FAIL/BLOCKED`。执行调度使用 `DRAFT/READY/RUNNING/READY_FOR_REVIEW/CHANGES_REQUIRED/VERIFIED`。Stage 裁决使用 `PASS/NO_GO/BLOCKED/WAIT_BUDGET/WAIT_AUTH`。三类状态不得互相冒充。

## 最小闭环

```text
冻结 Stage Packet
-> 派生 Workpack
-> 隔离实现
-> 实现收据
-> 受控自动验收
-> 隔离独立复算
-> Codex 门禁裁决
-> 必要的人类签署
```

运行：

```bash
python3 tools/verify_governance.py
python3 tools/verify_governance.py --self-test
```

两条命令只验证制度结构和负例拒绝能力，不是 LVW 产品验收。

## V0 范围、输入输出与非目标

V0-Min 提供单图→本地模型→raw/建议→显式采纳→人工四输出→复制/TXT/JSON；V0.1 增加最简短视频、文件边界与资源/取消；V0.2 补离线、增量安装/回滚、质量验证。V0 无持久任务数据库，Comfy 不可用时不保证界面可用；独立 React 服务是 R1a/V1 路线。

图片 JPEG/PNG/WebP，≤20 MiB/40 MP，长边≤1024；视频 MP4/MOV，≤256 MiB/60s，源单帧≤8294400 像素，默认四帧、送模型长边≤768。短片只有 1–3 个不同时间点可少帧并警告，不复制同帧。8 帧高级配置未验证，不开放。原媒体不变，记录源 hash、尺寸、实际采样时间性质和局限。精确长片分镜、ASR、训练、下载模型、任意网络输入、资产库、V2/V3 对端集成均不是 V0 交付要求。

四输出为自然中英、图像 Prompt、视频 Prompt、标签，负向可空。静图运动属于创作补充，不当成观测；英文缺失明确展示，CPU 格式化不能伪装翻译。用户稿与 raw/建议分离，分析失败、拒答、重试、取消和晚到均不得自动覆盖人工内容。不增设 NSFW 审核/审批，不承诺本地模型永不拒答。

## 3. M2 — truthful phase inventory, FAIL vs NOT_RUN, durable barrier

### 3.1 C8 — the attempt ledger (one small local helper)

A module-level ledger, used by the two M09 phase helpers and by the outer
`test_n10_r10` test:

```
_PHASE_STATES = ('PLANNED', 'ATTEMPTED', 'PASSED', 'FAIL', 'NOT_RUN')

class _PhaseLedger:
    def plan(self, name):        # named before it runs
    def attempt(self, name):     # AT THE MOMENT the operation is entered
    def pass_(self, name):       # only after every assertion of it held
    def fail(self, name, reason):# it was attempted and it failed
    def state(self, name):       # PLANNED / ATTEMPTED / PASSED / FAIL
    def names(self):             # in the frozen order
```

The ledger is **not** a framework: it is one small class next to
`_OwnerRegistry` (`T10:214-254`) with the same shape (a lock + a list) and
the same purpose (remembering, never deciding).

### 3.2 State-transition table

| from | event | to | durable document |
|---|---|---|---|
| `PLANNED` | the operation is **entered** (`attempt()` — called *before* the construction, the phase body or the stop call) | `ATTEMPTED` | none yet |
| `PLANNED` | the end of the test, the operation was never entered | `NOT_RUN` | `{'status': 'NOT_RUN', 'reason': <type of the first failure>}` — **no facts of the phase** |
| `ATTEMPTED` | the raw facts are written (durable, before the assertions) | `ATTEMPTED` (unchanged) | `{'status': 'EXECUTED', ...raw facts...}` |
| `ATTEMPTED` | every assertion of the operation held | `PASSED` | rewrite of the same path: `{'status': 'PASSED', ...raw facts...}` |
| `ATTEMPTED` | an assertion raised **or** the operation itself raised | `FAIL` | rewrite of the same path: `{'status': 'FAIL', 'executed': True, 'reason': <type>, 'detail': <str>, ...raw facts...}` |
| `PASSED` / `FAIL` / `NOT_RUN` | anything | unchanged (**terminal**) | never overwritten by the inventory |

### 3.3 Document lifecycle table

| document | written when | final status written by |
|---|---|---|
| `<phase>-barrier` | **before** the first assertion that depends on the barrier | the phase (PASSED) or the failure handler (FAIL) |
| `<phase>` | the raw facts, **before** the assertions | the phase (PASSED) or the failure handler (FAIL) |
| `<phase>-first` / `<phase>-second` | right after the corresponding **actual** stop returned | the phase (PASSED) or the failure handler (FAIL) — an **attempted** stop that raises is FAIL, never NOT_RUN |

`write_phase` (`T10:149-155`) overwrites the file at the same path, so the
"raw facts" write and the "final status" write are the **same** document:
the final status never erases the raw facts, it adds the verdict.

### 3.4 C9 — a document is marked *written* only **after** persistence succeeded

**Current (`T10:4104-4116` and `T10:4458-4463`):**

```python

    if inventory is not None:

**Proposed (C9):**

def _m09_timeout_phase(document, plan, tmp_path, *, phase, confirm_the_worker,
                        hold_the_worker, barrier_probe='EXACT',
                        expect_barrier='PASSED', inventory=None, ledger=None):

    ledger.plan(phase+'-first'); ledger.plan(phase+'-second')

                         hold_the_worker=hold_the_worker)

        api, document, plan, tmp_path, clock=clock)

        session.start()

            api.barrier_entered.wait(15.0)             # bounded wait
        barrier = dict(api.barrier)                   # the ACTUAL facts
        raw[phase + '-barrier'] = {...}                # the facts of the barrier
        record(phase + '-barrier', {'status': 'EXECUTED', 'barrier': barrier,
                                     'barrier_expectation': expect_barrier, ...})
        # -- only NOW the assertions of the phase ------------------------
        assert api.read_waiting.wait(15.0), ...
        ...
        record(phase, {'status': 'EXECUTED', **raw[phase]})
        assert <the assertions of the phase>
        ledger.pass_(phase)
        record(phase, {'status': 'PASSED', **raw[phase]})     # the rewrite
        # -- the FIRST real stop ----------------------------------------
        ledger.attempt(phase + '-first')
        first = session.stop()                        # a raise here => FAIL
        raw[phase+'-first'] = {...}
        record(phase+'-first', {'status': 'EXECUTED', **raw[phase+'-first']})
        assert first_facts.get('channel_reader_error') == 'RuntimeError', ...
        assert first['broker_retained'] is True
        assert first['state'] == 'UNKNOWN_RETAINED'
        ledger.pass_(phase+'-first')
        record(phase+'-first', {'status': 'PASSED', **raw[phase+'-first']})
        # -- the SECOND real stop ---------------------------------------
        ledger.attempt(phase+'-second')
        second = session.stop()
        ...
    except BaseException as error:
        for name in (phase, phase+'-barrier', phase+'-first', phase+'-second'):
            state = ledger.state(name)
            if state == 'PASSED':
                continue                              # a passed document is final
            if state == 'ATTEMPTED':
                # it was EXECUTED and it failed: an explicit FAIL that keeps
                # the raw facts and the barrier facts
                record(name, {'status': 'FAIL', 'executed': True,
                              'reason': type(error).__name__,
                              'detail': str(error),
                              'barrier': dict(api.barrier),
                              **raw.get(name, {})})
                ledger.fail(name, type(error).__name__)
            # a PLANNED name is left to the outer inventory (NOT_RUN)
        raise
    finally:
        ... # the bounded teardown of the phase (unchanged)
```

**The three residual triggers are closed by construction:**

* **Trigger 1 (executed failure without FAIL):** the failure handler now
  rewrites the document of **every attempted** name as `FAIL`, including a

  A name in state `PASSED` is skipped — a passed document is terminal.

  runs **before** `session.stop()`. If the stop raises, the name is
  `ATTEMPTED` → the handler writes **FAIL** (with the exception type and the
  live facts), never `NOT_RUN`.
* **Pre-inventory failures:** C12 moves the inventory to the top of the test.

**Current (`T10:326-360`):** only `RuntimeError` from `join` is caught; **any
other** exception from `join`, and **any** exception from `is_alive()`,
aborts the iteration — the remaining owners are never joined and the proof
document is never written.

**Proposed (C18):**

```python
def _salvage_threads(owners, *, seconds=10.0, states=None, total_seconds=30.0):
    facts = []
    hints = states or {}
    deadline = time.monotonic() + total_seconds
    for name, thread in owners:
        state = _owner_start_state(thread, hints.get(name))
        if state != 'STARTED':
            facts.append({'name': name, 'start_state': state,
                          'started': None if state == 'UNKNOWN' else False,
                          'alive': None, 'joined': None, 'error': None})
            continue
        error = None; alive = None; joined = False
        try:
            wait = max(0.0, min(seconds, deadline - time.monotonic()))
            thread.join(wait)
        except BaseException as exc:                 # ANY failure of the join
            error = {'type': type(exc).__name__, 'detail': str(exc)}
        try:
            alive = bool(thread.is_alive())
            joined = not alive
        except BaseException as exc:                 # ANY failure of the query
            error = error or {'type': type(exc).__name__, 'detail': str(exc)}
            alive = None; joined = False
        facts.append({'name': name, 'start_state': state, 'started': True,
                      'alive': alive, 'joined': joined, 'error': error})
    return facts
```

Properties:

* **Every** owner is attempted — a failing `join` or a failing `is_alive` is
  recorded and the iteration continues.
* The failure is **retained**, not swallowed: it is in the facts of the owner
  and it **fails the proof** (`_prove_salvage` must return a failure for an
  owner with `alive is None` or `error is not None`).
* The cleanup is **bounded**: at most `seconds` (10 s) per owner and at most
  `total_seconds` (30 s) for the whole salvage; the wait of an owner is
  cropped by the remaining total.
* The salvage is **separate** from the product: it renews no deadline of the
  round, it erases no retained resource and it never claims that the product
  released anything (the docstring of `T10:326-339` is kept).

**Proposed (C20):**

```python
def _capture_stop(session):
    captured = {'returned': None, 'exception': None, 'live_state': None,
                'retained': None, 'retained_broker_id': None,
                'background_threads': None}
    if session is None:
        return captured
    try:
        captured['returned'] = session.stop()
    except BaseException as error:
        captured['exception'] = {'type': type(error).__name__,
                                 'detail': str(error)}
        # the live state and the retention are read NOW, before the salvage
        try:
            captured['live_state'] = session.state
            captured['retained'] = session.broker is not None
            captured['retained_broker_id'] = id(session.broker)
            captured['background_threads'] = session.evidence().get(
                'background_threads')
        except BaseException:                     # the facts stay visible
            captured['live_state'] = 'UNKNOWN'
    else:
        captured['retained'] = session.broker is not None
        captured['retained_broker_id'] = id(session.broker)
    return captured
```

The stop exception is never discarded, and the live state / retention of the
moment are recorded **before** the salvage of the fixture.

does not own (`if id(thread) not in armed_threads and thread.name not in
owned_names: return original_start(thread, *args, **kwargs)`); the ownership
proof always works on the object, and a name match alone never claims
ownership.

**(c) No production decision is frozen** — the seam observes only: it
forwards the original start, never blocks, refuses, reorders or delays a
start, and never touches a deadline.

**(d) The bounded drain, ONE overall bound** — `pending_starts() == 0` alone
is withdrawn as a proof (a start may follow the snapshot). The salvage of a
round is a bounded drain loop: `budget = 30.0` (one overall bound per
round), `deadline = now + budget`; then repeatedly — take `registry.snapshot()`
(the exact objects and their states) and append it to `attempts`; release the
gates of the round; `_salvage_threads(snapshot.owners, states=snapshot.hints,
seconds=10.0, total_seconds=max(0.0, deadline - now))`; stop when
`quiescent` (no pending start, no late start) **and** the salvage is proved,
or when `now >= deadline`. The last snapshot and the last salvage are the
recorded facts.

* The **30 s** is the bound of the **whole drain of that round**, not 30 s per
  resnapshot; the per-owner wait is cropped by the remaining overall budget
  and the budget is **never reset** between the rounds of the loop nor between
  the rounds of the test.
* The quiescence assertion comes **after** the drain, never before it: an
  unquiet round is a **FAIL/UNKNOWN** — the gates are still released and
  **all** the registered owners are still attempted; the drain repeats
  boundedly; if the bound is reached the proof fails truthfully (`'the owners
  of the round were not quiescent'`) with the last snapshot and the last
  salvage recorded.
* The drain never renews a deadline of the product and never claims that the
  product released a resource.

**(e) The producers** are the ones the product starts: pump and heartbeat
(`C:1772-1783`), closer (`C:1530-1534`), channel drain (`B:5256-5278`), the
two endpoint workers (`B:4683-4702`) — all observed, because the seam
observes every `threading.Thread.start` of the armed window.

### 10.4 (D4) — the exact close failure, the exact unwinding order

**(a) The substring test is withdrawn.** The oracle is exact: exactly one
recorded failure; `owner == 'controlled:transport'`; `type == 'RuntimeError'`
(the exact class); `detail == 'controlled_close_failure'` (the exact
message); and no record with another owner or another type. In **every**
checkpoint `child_close_failures` (`T10:2929-2964`) must be **empty**: an
unrelated close or endpoint error fails the subcase instead of being
tolerated next to the intended failure.

**(b) The exact ordering** for the four checkpoints whose deliberate failure
is raised by the fixture: (1) the deliberate failure is **raised** inside the
region (sentinel / ordinary assertion / constructor seam); (2) the region
runs **every** cleanup action in a fixed order — the gates → the close of the
transport → the close of each endpoint → `_capture_stop` → the owner
enumeration → the drain + salvage → the proof → the document; (3) the region
**records** every additional error and raises `AssertionError(proof)` **only**
when no original failure is unwinding; (4) the original failure leaves the
region and is caught by the outer `except`, **after every other cleanup
action has been attempted**; (5) the outer `except` records the exact type
and the exact token.

`CLOSE_FAILURE` is the single case whose failure is produced **by the
cleanup itself**: the failing close is **recorded** with its exact type and
exact message and the region **continues** with every other cleanup action —
it is therefore **not** an unwinding case, and the design says so instead of
claiming it. No expected sentinel is caught before the cleanup region: the
outer `except` is the only catch and it lies outside the region.

**(c) The original failure is preserved** — an error met by the region while
an original failure unwinds leaves the **original** re-raised, the additional
error recorded in the document and the overall proof failed; the test never
reports a successful cleanup on an error.

### 10.5 (D5) — every cleanup error is preserved

**(a) The classification is inside the per-owner guard** (it was outside the
try of the salvage in §4.5). Per owner: `state = None; errors = []`; then
`_owner_start_state(...)` inside its own `try` (a failure ⇒ an `errors`
entry of kind `STATE` and `state = 'UNKNOWN'`); if the state is not
`STARTED` the owner is recorded with `alive=None, joined=None` and its
errors; otherwise `thread.join(wait)` in its own `try` (kind `JOIN`) and
`bool(thread.is_alive())` in its own `try` (kind `LIVENESS`, `alive = None`
on a failure); the fact of the owner keeps `alive`, `joined` and the **list**
`errors`.

* **every** owner is attempted — a failure of the classification, of the join
  or of the liveness query never aborts the iteration;
* every error is retained in a **list** with its kind, exact type and detail
  — never a single "first error", never a silent `UNKNOWN` without a
  diagnostic; an owner whose classification failed is `UNKNOWN` **with** the
  diagnostic and it fails the proof, which names the owner and the error;
* the display form (the thread name) and the identity (`id(thread)`) are
  separate fields — the identity is never read out of a display string.

**(b) `KeyboardInterrupt` / `SystemExit`** — the interruption is recorded
with its identity; with no original unwinding it is re-raised at the end of
the region; with an original unwinding the **original** is preserved and
re-raised and the interruption is an additional recorded error. The region
never reports a successful cleanup when an interruption occurred.

**(c) `_capture_stop` reads the real facts** — the **real** keys of the
evidence DTO (`C:2343-2444`), among them `background_threads`, which **is** a
valid key (`C:2399-2406`); the object identities are kept apart from the
display JSON. The capture holds: `returned` (the actual dict of
`session.stop()`), `exception` (`{'type','detail'}`), `live_state`
(`session.state`), `evidence` (the full dict of `session.evidence()`),
`evidence_state`, `evidence_broker_retained`, `evidence_failures`,
`evidence_background_threads`, `evidence_closer_start_state` (the real keys
of that dict), `retained_broker_is_session_broker` (a bool: the identity),
`retained_broker_id` (`id(session.broker)`: the identity) and `snapshot_error`
(`{'type','detail'}` when the snapshot failed).

* the identities are **not** read out of the display JSON — they are the live
  facts of the session; the display JSON is kept as the DTO it is;
* a valid key is never read through a `.get()` that could hide an absent
  value — a missing value is a fact to be asserted;
* if the snapshot raises, `snapshot_error` carries the exact type and detail
  and the capture is **not** silently empty;
* the capture is taken **before** the salvage and on **both** paths.

### 10.6 (D2, D6) — the state transitions after the corrections

| from | event | to | durable document |
|---|---|---|---|
| `PLANNED` | the operation is entered (`attempt()` **before** the construction, the phase body, the barrier or the stop) | `ATTEMPTED` | none yet |
| `PLANNED` | the end of the test, never entered | `NOT_RUN` | `{'status': 'NOT_RUN', 'reason': <type of the first failure>}` — no fact of the phase |
| `ATTEMPTED` | the raw facts are written, before the assertions | `ATTEMPTED` | `{'status': 'EXECUTED', ...raw facts...}` |
| `ATTEMPTED` | every check of the operation held | `PASSED` | the **check** document — terminal |
| `ATTEMPTED` | an assertion raised or the operation itself raised | `FAIL` | the check document: `{'status': 'FAIL', 'executed': True, 'reason': <type>, 'detail': <str>, ...raw facts...}` |
| `ATTEMPTED` | the phase reached its end | `PASSED` / `FAIL` | the **result** document, written **last**; PASSED only when the barrier check, both stop checks **and** the cleanup passed; a later failed stop ⇒ FAIL while the earlier checks keep PASSED |
| `PASSED` / `FAIL` / `NOT_RUN` | anything | unchanged (**terminal**) | never overwritten by the inventory |

The **result** and the **check** documents are different: the result carries
the overall outcome, the checks carry their own facts; a failed check never
rewrites a passed check and the inventory never rewrites either.
