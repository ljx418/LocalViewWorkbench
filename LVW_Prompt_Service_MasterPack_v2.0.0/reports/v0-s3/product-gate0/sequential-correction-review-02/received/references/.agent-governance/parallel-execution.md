# 并行执行与恢复

## 默认容量

- 本项目当前最多一个实现 Agent，单实现工作区上限一个；替代此前两个实现槽位的起始建议。
- 一个独立审查槽位。
- 一个 Codex 门禁队列。
- CI 并发受实际 CPU、RAM、GPU、端口和测试数据约束。

这是起始参数。审查积压时暂停非关键新实现，优先验收、修复和接近 PASS 的 Stage。

## 隔离规则

- 每个并行写任务使用独立 Git worktree 或等效副本；当前仓库未产生首个 commit 前不得启动并行写入。
- 一个 Workpack 一个实现负责人，不允许两个 Agent 无协调修改同一候选树。
- 独立隔离端口、数据库/schema、临时目录、fixture、服务、凭据权限和证据根。
- 公共 API、Schema、同一状态机、高耦合迁移和同一核心文件默认串行。
- 独立审查使用只读候选或隔离副本，不在实现工作区直接修复。
- 合并前重新绑定候选 SHA、Stage Packet manifest 和验收哈希，并重跑受影响门禁。

## 跨项目队列

队列项必须包含 `project_id/stage_id/workpack_id/dependencies/owner/worktree/resource_locks/budget/status/next_action`。只有依赖通过、Stage 已冻结、范围明确且资源锁可获得时才能进入 `READY`。

运行态数据默认写入项目外受控状态目录；仓库中的 `runtime/` 仅定义布局。不得把 Cookie、token、私有媒体、绝对私有路径或原始模型密钥提交到仓库。

## 失败与恢复

连续两次同路线无新证据时停止并交接。交接至少包含目标、起始/当前候选、修改、命令、真实日志、已排除假设、阻塞、预算和下一动作。恢复时重新核对用户指令、工作树、当前控制文件、最后通过门禁和资源所有权，不依赖聊天记忆，不重做已封存阶段。

## 2026-11-13 用户批准：Agent 容量与子阶段回收

- 每个工作区最多存活一个 Agent（主控、实现、独审各一）；项目最多三个。不同任务需要并行时必须先满足所有权与隔离规则，不能在同一空间堆积窗口。
- 派生前必须盘点 Orca terminal list、worker-list 及可见布局；计数包括忙碌、空闲、等待授权、WAIT_BUDGET、未确认退出和身份未知的 Agent。仅任务结束不等于进程退出。先复用合适原实例，否则归档、关闭并确认退出后才能替换。
- 使用 tools/verify_agent_capacity.py --worktree <精确工作区ID> --additional 1 检查。已有 Agent 时不得先派生再清理；无法确认容量时停止派生。普通构建服务终端按明确白名单登记，不能靠改名排除未知 Agent。
- 子阶段结束、纠偏实例被替代或独审回报完成时，先保存候选、命令、原始输出、结果、风险和恢复点，再执行受控回收。默认不使用 keep-open；当前仍执行的窗口保持可见，完成后及时回收。
- 优先用 orchestration worker-release 回收已结算 worker。遇到 retained/unknown 先读具体原因，不把它计作已关闭。用户明确要求清理废弃窗口时，可对已归档、已结算、确认不再承担工作的精确终端使用 terminal close；拒绝或退出不明不得强杀或改用其他宿主绕过。
- 不批量清空空间，不删除工作树、分支、源码、未跟踪工件或聊天证据，不关闭主控和仍在使用的用户窗口。关闭后重新列举确认窗口与进程实际状态。
- 429立即停止规则和独审隔离不变。容量不足进入调度阻塞，不降低验收门限、不新增预算。恢复原任务时核对上次绑定/计数器，不能借新窗口重置次数。
- 每次停止报告补充：当前各空间存活数、已回收窗口数、保留理由和下一回收时点。
