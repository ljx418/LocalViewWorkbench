# Owners and version1 storage

storage.py owns SQLite connection/transaction/schema bootstrap and stable failure translation. repositories.py is the sole SQL owner for media/shot/revision/idempotency; revisions.py owns canonical PromptSpec content SHA and immutable revision operations; shots.py owns CAS draft/head semantics and reusable API-facing service logic. main.py only wires repository lifetime/routes; media.py stages/validates copies and consumes the injected repository. models.py may add exact canonical Shot/ShotCreate/Revision/RevisionCreate types; existing Job/Analyze/Media/PromptSpec shapes stay compatible. Do not edit service.py/provider/runtime/native/tools or existing tests.

DB is settings.data_root/lvw.sqlite3. Only fresh empty DB initializes version1 atomically; schema_version, media_ref, shot, prompt_revision columns/types/FKs match contracts/storage.sql. No version2/design1.1 SQL and no V2/V3 tables or FTS are created. Existing supported version1 must have validated required core/private shape; unsupported/malformed/nonempty-unversioned DB fails before persistent schema/data writes, never auto-recreated, dropped or implicitly upgraded. No legacy migration is claimed. New DB bootstrap failure rolls back completely; preexisting data remains unchanged. Keep WAL/foreign_keys and bounded busy timeout<=2s on supported DB only. Per-operation connections/context managers or a clearly owned application connection must close; no request/model I/O inside DB transaction. Health/editor startup must not require model and DB errors must not erase drafts. Route errors may be503 without pretending DB success.

Private tables (not public DTO changes): media_blob(media_ref_id PK/FK media_ref, stored_name TEXT, stored_sha256 TEXT, stored_bytes INTEGER); idempotency_record(scope TEXT,key TEXT,payload_sha256 TEXT,response_ref TEXT,PRIMARY KEY(scope,key)). All fields NOT NULL, stored_bytes>=0; source metadata stays in media_ref.metadata_json as full canonical MediaRef. scopes media.upload/shot.create/revision.create. New private revision no-delete trigger supplements canonical no-update trigger, both error IMMUTABLE_REVISION. No additional public column renames or second schema owner.

MediaRef.sha256/bytes describe original upload; sanitized PNG is a derived copy with its own stored hash/size in media_blob. source_root_id/relative_path remain null for uploaded copies. stored_name is a validated generated basename within owned media root, never an absolute/browser path; reject traversal/symlink/reparse or substituted copies before serving/provider use. Do not compare original SHA to transformed PNG. Same content under another idempotency key is not silently merged. File is staged then atomically registered with upload idempotency; on rollback/duplicate clean only the new uncommitted owned copy, never the committed canonical copy or unrelated file. Durable rows must never reference a discarded staging copy.

Shot.spec is the human working draft; head_revision_id is the last explicitly saved immutable revision. POST shots creates no revision/head=null. PUT shots requires If-Match, updates draft/title/validated media association and ETag only; does not move head or rewrite history. POST revisions requires Idempotency-Key+If-Match and parent_id==current head (null initially); one transaction inserts immutable snapshot, sets head and draft to that snapshot, changes ETag and records idempotency. Read old revisions unchanged after later edits. Explicit user PUT may change locks; automatic analysis must not write any shot/revision. Human/imported source_run_id returns null; model_adopted cannot be fabricated. Lock strings/text/language fields preserved byte-for-byte under canonical JSON semantics.

One revisions.py content hash: SHA256 UTF8 sorted-key compact JSON of complete canonical PromptSpec, ensure_ascii=False, allow_nan=False; random ids/author/timestamps excluded. Persist quoted strong Shot ETag as edit token; same committed state returns same tag after restart, every successful draft/head change produces a new tag. All CAS checks and updates occur in one write transaction, not precheck then unconditional UPDATE. Idempotent replay of same operation/key/payload returns original resource without duplicate revision or ETag movement, even if original precondition is now old; mismatched payload always409. Header presence still required. Returned idempotent revision is immutable even after later heads.

Revision list uses canonical {items,next_cursor}, limit1..100/default30, deterministic keyset order (created_at,id), cursor bound to shot and validated/opaque, no arbitrary SQL/offset-only drift; invalid/cross-shot cursor422. Missing resources404. DB busy/unavailable503, missing If-Match428, stale ETag412, wrong revision parent409, invalid schema/extra fields422. Stable errors listed in stage-control.json. Unknown or failed transaction never maps to HTTP200.

New manual request validation must enforce all required canonical PromptSpec/nested Evidence keys and JSON scalar types, not fill required fields merely because an old model default exists. No new dependency. For PP04 use a genuinely transformed synthetic fixture (e.g. JPEG); identical source/copy bytes for an already canonical PNG are legitimate, never force a different image just to change its hash.
