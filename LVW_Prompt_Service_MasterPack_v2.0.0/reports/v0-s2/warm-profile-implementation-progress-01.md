# WP-S2-03/04 warm profile and resource worker implementation

Status: offline implementation; native runtime compatibility and real performance remain NOT_RUN. Decision: warm-profile-decision-01.md, packet 1.0.4. Fixed acceptance IDs, 10+10 denominator, numeric thresholds, business Schema and external authorization unchanged.

Production integration: BridgeOwner's optional warm scope is selected by the normal registered image/video owners through a trusted runtime factory. Default launches retain keep_alive=0 and per-frame cleanup. Explicit run-owned mode reads a bounded immutable binding under the isolated Comfy temp directory, shares one process-local counter (ten images, ten four-frame videos), validates expiry/digest and rejects budget overrun before another provider call. The launcher removes inherited benchmark flags by default; warm mode changes only the child environment.

The warm path retains only during an inference request, records pre-call /api/ps and resource admission with payload/raw hashes, then positively unloads before return. Native admission checks listener PID, CIM UTC creation ticks and bounded ancestry for GPU PIDs; the Comfy PID is admitted directly and not traversed to unrelated ancestors. A changed/reused listener, foreign GPU process, expired/changed binding, unexpected model/digest or nonresident model fails closed. Startup still requires <=4096 MiB; owned warm admission applies the unchanged <23552 MiB runtime threshold and RAM >=2048 MiB. The preloader owns cleanup on media-preparation failure; no GPU/provider work is added to invalid-file rejection.

Restoration has one absolute thirty-second deadline including root revalidation. Late empty inventory cannot turn a timeout green. Cleanup failure or interruption leaves the shared slot quarantined; the video state reports unknown when release is pending. Control/chat retain their own socket reference when HTTPConnection detaches a close response, preserving bounded reads and scoped cancellation.

Resource worker: tools/v0_s2_native_sampler.py, a low-level driver callable only after the parent Stage runner has bound and authorized it. It pins nvidia-smi bytes, streams index/memory at 1000 ms, uses native RAM and pinned read-only process handles for an explicit Private Bytes set, records process birth ticks, rejects gaps/overruns/thresholds without dropping samples, accepts only an owned stop marker, and terminates/waits only its own query child. Fresh output/receipt slots and executable post-hash checks prevent stale evidence. The process set is explicit; it must not be described as including unlisted dynamic children. The parent runner still needs source/runtime binding, process ownership, counter aggregation and cleanup proofs.

Generated native PowerShell lineage script parsed with PARSE_ERRORS=0 and no target queries; the recorded compatibility test now repeats that native parser-only check. All provider/telemetry/process streams in unit tests are explicit substitutes. No real model, GPU query, media decode, service or browser was started for this batch; only the native PowerShell parser ran.
