# Warm profile implementation decision 01

APPROVED_FOR_OFFLINE_IMPLEMENTATION by codex_gate_owner. Basis: docs/02_UX_TARGET.md temporary warm retention and restoration, docs/13 default unload, warm-benchmark-evidence-gap-01.md. No product Schema, fixed denominator, numeric latency/resource threshold or external authorization is changed. Packet revision 1.0.4.

Use a trusted process-local benchmark binding below the isolated Comfy temp directory, enabled only by explicit launch environment. Bind candidate, child authorization hash, program ID, model digest, actual owned Ollama listener PID and UTC creation ticks, issue/expiry (at most two hours), and exactly twenty measured requests. Ordinary launches keep the existing keep_alive=0 behavior.

The controller may preload its owned model before each measured request, recording preloads separately outside the timed hot request. They consume declared external/model-control budget; no preload or setup time may be subtracted from a timed request. Each public image/four-frame request starts resident, retains the model only within that request (keep_alive=300), and always restores unloaded state before returning. Failure/cancel also clean up; unproven release quarantines the shared slot. This avoids retaining a supposedly released request across samples.

Scope boundary: the preloader retains responsibility until valid media enters the inference scope. Invalid-file/preparation failures must still cause no GPU/provider actions in the media owner; the controller must unload its own preloaded model in its outer finally and record that attempt as failed. Never count such an attempt in the successful warm denominator. Root revalidation and inference-scope unload share one absolute thirty-second release deadline; interruption before positive restoration retains quarantine.

Every measured provider call must prove fresh model tag/digest/GPU residency via loopback /api/ps, GPU/RAM limits and actual owned process lineage. Accept the Comfy process itself and the bound Ollama process/descendants only, using listener ownership and creation ticks against PID reuse. No global interrupt or foreign termination. Benchmark admission uses the existing strict running threshold (<23552 MiB), not the cold prestart threshold, only after owned warm identity is proven; fresh service startup still requires <=4096 MiB. No threshold is relaxed.

Write bounded run-owned JSONL before each call and after its response, including request number, monotonic timing, payload/raw hashes and residency evidence; no image payload or instruction text. Final events prove restoration. The real runner must bind these events, sampler and public history; synthetic tests alone cannot pass S2. Startup binding is not a public user-facing API and grants no external run by itself.
