# Native Comfy browser worker decision 01

APPROVED_FOR_OFFLINE_IMPLEMENTATION by codex_gate_owner; packet 1.0.17. Existing business API/Schema, Stage/cumulative acceptance IDs, thresholds and preparation/full checkpoint/recheck budgets remain unchanged. Nine browser subchecks refine existing public UI/manual/cancel obligations; no browser or native action is authorized by this document.

Implement a real Playwright worker against the installed native Comfy app, not HTML/set_content or a DOM simulation. It loads the frozen public UI workflow through the app's normal frontend import routine, uses the actual upload input, native keyboard queue shortcut, real extension buttons and actual downloads/clipboard. Two UI queues are distinct declared cases: successful analysis/adoption, then a new run cancelled through the visible product control. Require the actual public owner and exact model/mode/instruction/timeout/upload reference in each intercepted /prompt body. Support only the bare and /api aliases of the same known Comfy API paths; do not rewrite requests, expand to other origins or let the browser call Ollama directly. CLI/frontend/SDK compatibility and selectors are still unverified on the installed target and must not be represented as native readiness.

Fixed worker subchecks: manual-initial, upload, native-analysis, busy-manual, explicit-adoption, exports-clipboard, late-adoption-new-run-cancel, offline-manual and node-removal. Require manual fields not overwritten by analysis, second-click confirmation before replacement, source/raw provenance in actual JSON, TXT/clipboard equality, a controlled clipboard denial preserving draft, old adopted provenance retained after later editing/new run/cancel, offline export after the parent proves its Ollama stop, and removal of the real node's editor DOM. Normal VM unit tests still cover the individual late-action branches; the real worker's held-response scenario combines pending adoption, edit, new run and cancel and must be reported with that exact scope.

One controlled adoption hold forwards an actual successful backend response unchanged: retain original bytes/hash/status, queue/edit/cancel while held, then fulfill with those exact bytes and retain the forwarded hash. Never construct a model result or replace its endpoint with a mock. Hold max150 seconds, resident-cancel readiness max120 seconds, one cancel and no replacement model attempt after a missed window. Actual cancel round trip must be <=1 second and carry the parent-bound current token/epoch. The parent independently joins native journal, real public history, provider prefixes, source PTS/hashes and sampler evidence; UI booleans, HTTP 200, screenshots or worker exit zero alone never pass a product obligation.

Use a fresh headless Linux Chromium process/session/context, no storage_state or persistent profile input, no existing browser profile. Pin executable bytes and actual /proc/exe bytes, original PID/birth/group/session, and the auto-created profile's inode/device before page navigation; send those facts to the parent for independent checking. Browser HTTP is confined to http://127.0.0.1:8191; only its ws /ws may connect. Deny other loopback services, cloud, proxy, file URLs and unsafe mutations; service workers are blocked. Bind the Playwright entry file explicitly, and require the parent to seal its full transitive dependency/source footprint before launch. No package install, browser download or upgrade is included. Force the S2 Comfy launch to a fresh run-owned --user-directory; existing user slots are rejected. Parent must prove the installed CLI honors that root before permitting writes to its finite settings/userdata scope; permanent configuration writes remain forbidden. Historical S1 Harness is unchanged.

Fixed worker budget: browser starts1, upload1, public submissions2, preview8, adoption2, cancel1, held response1, downloads6, ephemeral user writes<=16; all others are denied. Failed permitted actions consume their slots. The HTTP router consumes an armed queue before awaiting parent approval, preventing concurrent duplicate submissions. Every real upload/submission/owned user write is separately precharged through the parent before forwarding; graph/body hashes and artifacts are retained. Parent child authorization must include these budgets in the one complete Stage run, not a separate unapproved browser attempt.

Worker stdin/stdout is a bounded JSONL protocol (<=64KiB/record, <=512 requests, <=8 outstanding). Every reply must match kind, sequence, candidate, child hash and fresh nonce, with explicit approval. Replay/cross-run/refusal/disconnection aborts pending work and closes the worker-owned browser. Importing the module launches nothing; CLI requires the config plus live replies. No self-authorization or Stage PASS exists. Only the formal parent may approve after validating Mother/child/source/tool/sample/ports/processes/budgets and a fresh whole-candidate source gate. Deterministic tests may inject substitutes, but the CLI does not accept injectable dependencies from config.

Parent protocol obligations:
- preflight: validate active child and source identities before target media/executable reads.
- browser_start: independently seal native/frontend/Node/Playwright/browser dependencies, prove owned Comfy and ephemeral user root; grant launch only within the child.
- browser_owner: verify original Linux PID/birth/parent/group/session/executable and fresh profile facts before page use.
- upload/public_submit/user_write: charge exact finite operation, validate bytes/graph/path and root ownership before forwarding.
- case_begin/case_queued: capture owned roots, source/provider/sampler prefixes and actual UI graph/prompt ID, never fabricate a queue receipt.
- busy_manual: prove the matching current public run is still preparing/running during the export.
- case_finished analysis_before_adoption: recompute actual four-frame success/provider/source evidence and return its real token; later complete checks bind downloaded source/raw export to it.
- cancel_ready: bounded polling, return ready only inside a live owned resident-provider window for that second UI prompt; terminal/missed windows fail rather than retry.
- case_finished cancel: join actual acknowledgement/native cancellation/release evidence and preserve the previous adopted draft/source.
- offline_op: run the remaining default cancel/fault checks under their own budgets, prove owned Ollama absent while Comfy remains the same; do not substitute a mock provider.

Cleanup closes/kills only the owned BrowserServer handle, with bounded waits, verifies original exit and empty isolated process group, and removes only the captured same-inode owned temporary profile if needed. Never kill an arbitrary PID/group or delete an unrelated profile. Leave missing cleanup proof as NO_GO; parent still owns terminal process/temp/privacy cleanup and evidence retention. Record all nine rows including NOT_RUN after failure, raw network/action ledgers, actual files/screenshots with hashes and terminal cleanup.
