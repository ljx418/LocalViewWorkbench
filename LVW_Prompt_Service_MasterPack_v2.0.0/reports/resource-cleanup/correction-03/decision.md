# 纠偏03：独审03的03-A至03-H统一处置

不降低门槛、不改写旧失败、主干仍暂停。范围仍限用户明确授权Codex接替的资源清理增量。

- A：当前服务代次只读取一次；独立校验当前与lease两份代次均非空且有效，再比较。pending保存代次副本，不能让None==None授权停止。
- B：校验进程实际LVW_DATA_ROOT和TMPDIR与封存目录一致，产品导入前执行，不允许ambient default_app写到别处。
- C：v4使用标准库SHA256和固化的可信执行器摘要，在导入项目authority之前验证其字节。实际wslpath也加入原生执行器绑定并与PATH解析结果一致；其余工具和helper源图继续封存。该根摘要由架构方冻结，不由子授权自行提供。
- D：没有启动时独立采集的nonce/PID/birth时，终态只保存观察并报告unknown，不能从终态推导expected再自证；保留预算。正常启动前后两份身份必须匹配。
- E：独占claim创建后的短写、写失败、close失败都独立记录并进入保留预算/终态收据；重复claim的O_EXCL拒绝不越权终止原运行。
- F：JSON/PNG公共相对写入器先使用O_NONBLOCK打开再检查普通文件及单链接，FIFO无读者立即拒绝，不堵塞事件循环。
- G：生产清理响应记录操作内严格inventory观察的状态和数量；v4只有该观察确认0模型时才能标为空载服务关闭。loaded/unknown不得计入零模型证明。真实加载后释放和重启识图仍未验证。
- H：before/after/runtime/listener标记进行中；总期限打断时记录interrupted，尚未开始的观察才为skipped/not-observed，不抹去已发起事实。

v1/v2/v3 CLI保留历史并退役；当前仅v4。新增回归驱动生产入口、代次翻转、产品导入前环境绑定、可信执行器漂移、claim故障、FIFO、启动身份缺失与中断观察。完整后端回归不缩分母，前端字节未变则按既有冻结复用规则复用12项及构建证据，并重新验证真实页面/原服务退出。
