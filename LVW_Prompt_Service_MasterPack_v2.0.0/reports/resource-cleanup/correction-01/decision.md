# 资源清理纠偏01：独审13项一次性处理

根审查负责人决定：采纳独审01的10项Major和3项Minor，不争辩其已通过的22项CPU结果，不将旧候选或旧实时空载证据升级为完整通过。主干持久化仍暂停；本次仅在用户明确交接范围内修正资源清理。

## 兼容设计纠偏（覆盖初始执行包相应条款，其余安全边界保留）

清理不再通过Ollama端口POST卸载，也不调用遗留lease的provider.release。lease、模型tag和旧监听positive均不足以授权当前端口写操作。改为：本轮运行时原生owner通过stop nonce指令，使用其一直持有的原始进程句柄退出自己的模型服务。对端口仅做只读状态观测，不会误卸载替换监听者。未知归属和外部模型拒绝；没有原生owner不能清理遗留lease。UI明确关闭模型服务，下次先点击启动，不承诺自动重新装载。

动作前核验完整、不歧义的name/model/digest/size_vram；动作后匹配原nonce/PID/birth的exited记录、确认本轮wrapper退出，并采样3次资源边界。比较lease原基线及装载前后估计的GPU范围（沿用1024MiB误差余量），不声称全机GPU清零。所有确认和返回runtime状态完成后才一次性清除lease；错误/替换服务/超时保留pending恢复记录与lease，不盲重放HTTP卸载。未知终态禁止启动新模型服务，允许后续仅核对同一个原句柄。

43秒总期限包括runtime锁等待；缺失的before/after/runtime必须有具体原因，不能裸null冒充观察。已确认退出后的重复清理可复核相同退出记录并返回noop，外部新服务仍不操作。

## 发现处置映射

1/2：删除清理路径上的所有模型卸载HTTP写操作；旧记录只定位原句柄，不授权端口。
3：严格字段一致性、空白、digest、重复条目和size_vram负例。
4：所有可失败观察先完成，lease/pending仅在最后同步提交；未知保持可恢复。
5：旧harness禁止直接运行；v2先验证DB封存、过期、文件/tool哈希和独占临时根身份。实时子授权明确允许一次本轮受管服务清理，空载观察不能冒充真实装载后释放。v2不递归删除临时目录。
6：v2逐步try/finally保留所有清理异常，始终写终态；native必须有匹配exited证明，未知保留预算。
7：v2范围为零模型调用，不保留尚未验证的图片/预装载分支；预算终态以账本实际calls为准，日志只导航。真实装载/再次识图继续BLOCKED，不能据此声称完整验收。
8：新增runtime/runtime_error/verification_scope；所有观察缺失带原因。
9：清理错误与重查错误分离，重查成功清除独立状态错误；只有HTTP404判断旧端点。
10：新执行包一次封存最终候选和v2 harness，旧ACK哈希不改写。
11：补生产ASGI client地址与恶意Host、非loopback负例。
12：夹具逐项名称标注fixture，不再混称real inventory。
13：期限放在取得runtime锁之前。

新增用例不是删除失败测试制造绿；初始wire卸载用例随该API写实现移除，被“禁止任何卸载POST/原句柄stop/替换服务/lease最终提交”生产行为测试替换；独审重新核验全部新固定清理用例及累计回归。
