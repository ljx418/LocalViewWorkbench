# 待独立架构复核：视频外观与时序证据职责拆分

状态：PROPOSED，不是实现许可或Stage通过；原UM04视频质量失败不改写、不删除义务。先确认当前原生多图输入确实可见全部四图，再判断此路线是否符合现有合同。

## 问题与边界

live12/13/14、thinking1536和完整原帧03均没有让当前Gemma可靠描述周期纹理相对位移；03独审确认原始模型错误称完全静止，并在negative中压制真实变化。停止同类提示、thinking和图版调参。真实像素/图像注册可复算，但它们不单独证明物理相机或具体物体运动。

保持PRD目标、公开API/Schema、固定UM10、原tracking输入、质量/资源门限、一次Provider、全部实际采样帧、raw/建议/人工稿隔离和人工签署。不得通过删模型错误句子、将其改写为正确答案、缩分母或把新合成样本替换旧视频制造通过。

## 候选职责

- VideoKernel仍唯一管理实际帧/PTS/源SHA与纯CPU视频事实；复用现有像素差异/灰度与色分量注册，数值与局限完整留证，不以色分量命名物体/背景或推出物理方向。
- OllamaProvider仍一次请求实际全部源帧，负责逐帧可见外观、主体/姿态、场景与风格和真实双语描述。内部响应按实际frame_id逐帧验证，不能只看末帧；不要求模型承担它已反复失败的精密几何运动判断。每帧原文及最终共享外观原文保留。
- CPU compiler只按明确来源组合机器建议：模型逐帧外观原文 + 程序计量/不确定性。时序描述必须区分“像素不相同”“有界配准的平移拟合特征”“物理相机/主体动作未知”；不能把数值拟合冒充已证实的背景/物体运动。
- AnalysisService继续唯一任务/取消/发布owner。ModelRun.raw_response保持实际网络模型最终内容原文；parsed_spec注明机器外观与计量组合来源，显式采纳才进入人工稿。图片路径不改，无新依赖/模型下载。

## 需要独立裁决的合同问题

当前UM04写“真Provider全采样帧语义与原始输出”。新路线仍真调用Provider观察全部帧，但几何计量归程序而不是模型运动文字；现有产品合同是否强制原始模型必须承担camera_motion/subject_action？若是，这将改变验收义务，不能据本提案自行实施或宣称PASS，应提出精确产品变更请求。若仅内部Producer职责调整且用户最终功能/真假边界保持，可由架构门禁负责人在COMPLETE03允许的非破坏性内部修正范围内记录ADR、独审并重新冻结packet，随后实现。

不允许把registration当事实核验器：任何原始模型字段如果仍对整体视频作错误静止/不变断言，独审仍应判FAIL；不能通过parsed_spec追加正确文字抵消错误raw。新的外观任务应避免时序臆测，但是否实际做到必须真实验证。

## 验收不降级

- 原tracking必须保留，最终视频提示词必须承认受证据支持的采样变化，不能称整个视频静止；物理成因/方向可保持未知。
- 所有实际源帧出现在一次生产请求，严格frame_id/原文绑定，四幅不同合成图仅用于证明输入可见性，不能替代tracking或11个人工留样。
- 程序事实测试含相同像素、亮度变化、噪声、平移、周期alias、局部变化、同/异色结构；无法确证时只保留测量与未知，不虚构语义或相机运动。
- 一并补齐UM02真实格式/大小/时长/像素/空/损坏拒绝及无残留；UM05真实queued/preparing/running取消；公开分析请求/配置收据复算。完成离线与独立代码审查后，只执行一份新鲜完整UM10，不拼接组件证据给Stage通过。

本提案不批准本身，独审必须指出是否属于降低现有合同；在该问题未清楚前不实施职责调整。
