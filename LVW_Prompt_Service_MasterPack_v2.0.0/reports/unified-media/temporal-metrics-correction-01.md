# 通用时序比较元数据纠偏（母授权02范围内）

依据：AUTH-PROGRAM-V1-LOCAL-02 已批准内部提示与输入组织在完整源帧不变前提下版本化；不改变公共合同、UM10固定分母或质量/资源阈值。

触发：候选0cc125f的live05完整生产链结束并清理，模型实际调用3次，但原始视频输出称背景/画面不变，与实际采样帧不符。旧失败原样保留，不能由新代码重命名通过。

假设：主物体维持同一位置会使模型忽略背景细微位移。只靠文字要求逐帧比较仍不足。新实现将每对实际解码RGB帧的不同像素比例和平均绝对RGB差作为输入元数据，与全帧时序图同时提供；不输出运动类别、方向、样本名称或预期答案。明确压缩/光照也会改变像素，不能将非零差值当运镜证明；方向/原因不明必须未知。

生产接线：OllamaProvider.analyze_video -> temporal_pixel_measurements(decoded.frames) -> 同一次_analyze_images用户消息与实际provider账本；全源FrameRef/SHA/PTS、全帧时序图、一次Provider请求、原始模型输出和显式采纳流程均保留。不会用CPU统计改写模型输出或伪造翻译。

离线验证：生产owner的HTTP传输夹具检查所有原帧仍在同一wire图且只有一次请求，并核对实际发送统计。独立2x2像素例覆盖完全相同、单像素变化、单帧、尺寸不匹配。不下载或增加依赖。

下一真实运行仅在新候选封存、CPU与独审通过、上轮终态完成后派生live06。它消费新母授权的第一次修正复验，非重放live05；样本、端口和每轮8动作/1800秒上限不变。
