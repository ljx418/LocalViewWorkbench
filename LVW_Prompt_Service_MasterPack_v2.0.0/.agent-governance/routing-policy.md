# 模型路由与预算政策

## 2026-11-12 用户规则：ClaudeCode 429 立即停止（最高优先级）

用户已确认ClaudeCode额度恢复，后续实现恢复由Orca可见ClaudeCode窗口承担。此前因额度不足启用的Codex临时实现覆盖结束。

ClaudeCode任一实现任务首次返回HTTP 429（包括rate_limit、额度或速率限制）时，立即停止该任务的后续实现、派发与重试，保存实际错误、候选/工作树状态、已执行命令与未完成事项，并报告WAIT_BUDGET；若原因无法从原始错误确定，保留UNKNOWN，不猜测配额已恢复。

不得自动重试429、循环等待后继续、切换账号/供应商/模型/Harness，或自动派生Codex/DSH/其他Agent接替这项实现。历史“继续开发”“剩余V1授权”或旧Codex临时接手授权均不能代替此次429之后的明确接手批准。

只有用户针对这次中断明确授权Codex接手，才可记录新的有限接手范围并恢复实现；不推断为其他任务或未来429的永久接手许可。用户明确恢复ClaudeCode任务时可按原候选/预算核验后恢复ClaudeCode，不等同允许Codex接手。禁止为绕过此规则购买额度。

Codex仍可保存证据、整理交接、维护坐标和汇报；这些动作不能变相继续被停止的实现。独立审查与人工签署不因接手而合并。每个ClaudeCode实现任务的派发指令必须包含本停止条件，Workpack模板引用本节。此规则覆盖旧文件中与“429后可自动由Codex临时实现”冲突的概括性条款；历史记录保留，不改写原授权。

## 默认路由

| 任务 | 默认执行者 |
|---|---|
| PRD、架构、合同、Stage 设计、重大争议、Stage 裁决 | Codex + Sol |
| 中等复杂度、多文件业务实现 | Claude Code + MiniMax |
| 小型实现、批量适配、脚本、夹具、仓库检索 | Claude Code + DeepSeek |
| 编译、类型、合同、固定分母和确定性回归 | 可信执行器 |
| 独立复算和证据检查 | 隔离的 DeepSeek 实例 |
| 复杂假绿、安全或语义争议 | Codex + Sol |
| 产品体验、高风险操作和最终发布 | 人类 |

路由是初始运营参数，不是能力排名。调整路由必须依据“通过独立验收的 Workpack 总成本”和可复现质量数据，不改变职责权限。

## V0 临时路由覆盖（历史，额度恢复后已失效）

因 Claude Code 当前无可用额度，项目负责人已授权在 V0 结束前由隔离的 Codex 实现实例临时承担 Claude Code + MiniMax 与 Claude Code + DeepSeek/DSH 的实现职责。该覆盖只改变执行载体，不改变权限边界：root Codex 仍是 Stage 门禁负责人；每个 Workpack 仍只有一个实现 owner；实现实例只能提交 `READY_FOR_REVIEW`；同一候选必须由未参与实现的隔离 Codex 审查实例复算，root 再作门禁裁决。额度恢复或 V0 结束时，本覆盖自动失效，后续路由须重新冻结。

## 预算规则

- Sol 建议预留 20%–30% 用于 Stage 收口、复杂审查和裁决；比例可依据指标调整。
- MiniMax 优先使用已有套餐，但不得因额度不足降低测试标准。
- DeepSeek 每个任务必须设调用、输出、工具和重试预算，并分别记录缓存命中与未命中费用。
- 预算耗尽且必要验证未完成时进入 `WAIT_BUDGET`，不得用旧证据、缩分母或降阈值通过。
- 同一失败路线连续两次没有新证据或进展时停止，保存交接并升级；不得无限重试。
- 谷时可用于非关键批量任务，但不能阻塞关键路径。

## 成本口径

```text
合格 Workpack 总成本
= 模型调用费 + 失败重试费 + 复审成本 + 必要人工介入成本
```

同时记录排队时间、执行时间、审查时间、首次验收通过率和返工轮次。任何模型别名都必须在运行前解析为实际 provider/model 并写入收据。

## 2026-11-11 当前生效角色覆盖

用户已重新指定ClaudeCode作为实现/局部自检负责人，Codex回归架构/合同/验收设计/协调/审核。此条优先于此前因额度不足启用的root临时实现路线。Orca负责可见窗口、独立工作区与任务回报；按已配置账户启动，不强制指定未核实的模型别名，不读出密钥。实现者局部验收只报READY_FOR_REVIEW，隔离审查/受控执行器/Codex裁决/人类签署分开。额度耗尽、登录或权限阻塞须如实报告；不自动更换供应商、不购买套餐。

## ADR-17效率增量

当前下一实现按可见ClaudeCode派发，Codex不再常规批量实现；只收敛重复工具职责，不先重建调度平台。一次集中纠偏，义务/负例先行；变更影响决定复验，固定分母和429规则不变。规范见workflows/delivery-efficiency.spec.json。
