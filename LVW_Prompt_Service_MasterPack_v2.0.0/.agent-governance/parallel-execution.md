# 并行执行与恢复

## 默认容量

- 两个实现槽位。
- 一个独立审查槽位。
- 一个 Codex 门禁队列。
- CI 并发受实际 CPU、RAM、GPU、端口和测试数据约束。

这是起始参数。审查积压时暂停非关键新实现，优先验收、修复和接近 PASS 的 Stage。

## 隔离规则

- 每个并行写任务使用独立 Git worktree 或等效副本；当前仓库未产生首个 commit 前不得启动并行写入。
- 一个 Workpack 一个实现负责人，不允许两个 Agent 无协调修改同一候选树。
- 独立隔离端口、数据库/schema、临时目录、fixture、服务、凭据权限和证据根。
- 公共 API、Schema、同一状态机、高耦合迁移和同一核心文件默认串行。
- 独立审查使用只读候选或隔离副本，不在实现工作区直接修复。
- 合并前重新绑定候选 SHA、Stage Packet manifest 和验收哈希，并重跑受影响门禁。

## 跨项目队列

队列项必须包含 `project_id/stage_id/workpack_id/dependencies/owner/worktree/resource_locks/budget/status/next_action`。只有依赖通过、Stage 已冻结、范围明确且资源锁可获得时才能进入 `READY`。

运行态数据默认写入项目外受控状态目录；仓库中的 `runtime/` 仅定义布局。不得把 Cookie、token、私有媒体、绝对私有路径或原始模型密钥提交到仓库。

## 失败与恢复

连续两次同路线无新证据时停止并交接。交接至少包含目标、起始/当前候选、修改、命令、真实日志、已排除假设、阻塞、预算和下一动作。恢复时重新核对用户指令、工作树、当前控制文件、最后通过门禁和资源所有权，不依赖聊天记忆，不重做已封存阶段。
