# 反假绿与证据约束

## 关键义务映射

每条关键义务必须可追踪为：

```text
义务 -> 生产 owner/公开入口 -> 测试驱动 -> 明确 Oracle
     -> 负例和 exact/one-over 边界 -> 持久终态 -> 清理证明
```

测试名、常量、文件存在、字符串搜索、HTTP 200、非空返回或 exit 0 均不能单独证明功能通过。Mock 可替代外部原语，但不能替代被验收的 owner、router、adapter 或状态机。

## 必须拒绝

1. 删除失败用例、缩小固定分母或修改阈值。
2. 用内部函数、直接 SQL 或旧产物替代公共生产入口。
3. Mock 替代必须真实执行的逻辑。
4. 捕获异常后返回成功；跳过/阻塞/未执行计为 PASS。
5. 证据绑定旧候选、旧规格或不同验收哈希。
6. 候选变化后无复用证明继续沿用旧结论。
7. 只测成功路径，不测失败、恢复、隐私和清理。
8. 实现者修改受保护的验收集合或为自己的候选签署独立通过。
9. 并行任务共享数据库、端口、临时根或凭据造成污染。
10. 手写摘要、Agent 自述或伪造日志代替执行器原始记录。

## 收据绑定

正式收据至少绑定：项目、Stage、Workpack、候选 SHA、规格版本、验收哈希、门禁版本、唯一 run、环境、逐项结果、固定计数、原始产物、风险、审查会话和裁决。正式收据优先由可信执行器写入候选代码控制之外的受控存储。

`PASS` 必须满足 `pass == denominator` 且 `fail == blocked == skipped == not_run == 0`。Fail-closed 除错误码外还必须证明无写入、无入队、无发布、终态 settle、生产者/消费者停止和临时资源清理。
