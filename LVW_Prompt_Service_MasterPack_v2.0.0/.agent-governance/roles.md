# 角色与权限

## 固定职责

| 角色 | 默认载体 | 负责 | 不得 |
|---|---|---|---|
| 架构与门禁负责人 | Codex + Sol | PRD、架构、公共合同、固定分母、Stage Packet、重大风险、门禁裁决、当前坐标 | 常规批量实现；审查自己的实现；代签人类验收 |
| 主实现负责人 | Claude Code + MiniMax | 冻结 Workpack 内实现、自检、真实运行、实现收据、修复 | 改冻结合同/阈值/分母；删除失败测试；宣布 Stage PASS |
| 补充实现负责人 | Claude Code + DeepSeek | 边界明确的实现、适配、脚本、夹具、局部修复 | 改全局规则；覆盖其他工作区；无限重试 |
| 独立审查者 | 隔离的 DeepSeek；复杂争议升级 Codex | 独立复算、生产入口、证据、失败/清理/权限/隐私检查 | 继承实现者结论；修改候选后为其签署 |
| 可信执行器 | CI/受控本地执行器 | 原始命令、退出码、固定分母、环境、结构化收据 | 用模型文字代替运行事实 |
| 人类负责人 | 项目负责人 | 产品/成本/风险取舍，高风险授权，UX/内容质量，最终签署 | 承担可自动化回归和字段核对 |

## 权限不变量

V0 期间的临时载体为：`codex_isolated_implementer` 代行主/补充实现，`codex_isolated_reviewer` 代行独立复算。两者必须是不同会话；root gate owner 不直接实现，也不把实现者自检当作独立审查。该临时授权不扩大外部运行、私有数据、付费 Provider 或环境写入权限。

- 一个 Workpack 只有一个实现负责人。
- 一个 Stage 只有一个门禁负责人。
- 同一候选的实现会话与独立审查会话必须不同。
- 实现者只能提交 `READY_FOR_REVIEW`，不能提交 Stage `PASS`。
- 独立审查者输出发现和建议结论，正式 Stage 状态只能由门禁负责人写入。
- 人类授权必须指向具体动作、输入、成本/重试预算和清理责任；“继续开发”不等于允许 Cookie、私有媒体、Provider、网络或可见浏览器。
- 实际供应商和模型由启动收据证明，不能依据 Agent 自述。

## 冲突升级

公共合同、固定分母、所有权、安全边界、真实数据有效性或高风险授权有争议时，立即停止 Workpack，状态进入 `BLOCKED` 或 `WAIT_AUTH`，交由门禁负责人或人类处理。
